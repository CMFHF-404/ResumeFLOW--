# 80% 目标推进：e 轮冻结结果

目标仍进行中，未达成。评分成功率 16/30（53.3%），优化服务成功率 12/16（75%）；已成功产出的 21 个改写候选全部获准。测试后段提供方额度耗尽，不能把受影响失败排除后宣称达标。

## 本轮改动与验证

- 统一覆盖审核提示词与返回结构，动态固定两个审核数组的记录数量、允许 ID 和各自判定词汇。
- 评分审核未形成有效结论的格式失败可使用剩余预算重试，正常路径仍为两次生成加一次审核，总计最多五次、150 秒。明确不合格报告不会被反复审核到获准。
- 后端完整回归 1,063 项：1,058 通过、5 跳过。受影响前端契约 31 项通过。
- 扩展审核门槛两轮 18/18 判断正确，分别耗时 31.13、16.53 秒。随后运行十份样本完整协议，期间未改变代码、样本或规则。

## 提供方额度阻塞

运行后段连续出现 HTTP 403。使用相同模型和鉴权进行了一次最小诊断，只保留受控分类、正文长度和哈希，确认原因为 `quota_exhausted`。没有切换模型、充值、修改本地计费数据或保存提供方正文。

复评分 24 次和盲评 8 次均因提供方不可用失败。优化另有两次提供方失败、一次响应解析失败和一次语义审核结构失败。这些失败全部保留，未重跑替换。恢复现有提供方额度是后续真实验证的必要条件，恢复前继续离线修复。

完整运行记录 179 次提供方请求尝试、已记录 1,475,509 tokens，墙钟 967.45 秒。失败请求可能没有完整用量记录。另有前置门槛两次及一次额度分类诊断，不混入完整协议的服务成功率。

## 下一步

评分生成端将优先改为可核对的逐项证据判断，服务端按既定五个专业表达子项及权重计算分数，保留独立审核和完整报告选择；同时继续定位语义响应结构失败。不得为达到 80% 调高低质量简历分数、放宽事实安全或剔除失败。真实额度恢复后，用新的冻结标签验证，不覆盖本轮。
