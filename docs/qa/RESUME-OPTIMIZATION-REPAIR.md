# 六维评价与优化：算法修复和真实模型回归

结论：优化的主要契约失败已显著减少，真实模型能够修复标点、恢复来源中的行动和量化成果。但**尚未达到所有维度稳定、所有可修问题都能稳定修复的完整验收标准**。原始失败数据不删除、不覆盖。

## 修复内容与原因

1. **模型重复生成服务端固定信息，造成整批拒绝。**回答改写改为候选补丁；字段身份、原文、问题维度、选择状态由服务端保留。无数据状态直接保持原文，不让模型重新输出整份方案。排序模块的唯一地址别名、同经历拥有完全相同文本的引用错位可确定性纠正；其他身份、来源错误继续拒绝。
2. **没有数字仍获得量化分；字段完整度随意扣分。**新报告按字段覆盖率和有证据的经历覆盖率校准。泛化文本、日期、否定或假设数值不能充当已实现成果。业务语义仍需模型绑定证据；代码不把任意数字都当业务结果。
3. **专业表达混入岗位匹配、成果大小和主观“深度”。**明确逐经历、分项等权的锚点；具体的协作行动、定性结果可以获得相应表达分，不能因为没有数值就被认定不客观。摘要重复不应抹去经历中已存在的全部专业证据。
4. **单次模型判断波动，修复调用耗时无界。**一次评价目标收集三份合格报告，最多五次生成，至少两份有效；按六维距离选取整份中心报告，保留该报告自身的证据、问题与分数。单次生成40秒、总体150秒；无效样本及连接超时有界处理，取消、用量和安全错误不作为普通样本吞掉。
5. **定向版本添加JD词汇，连带阻止通用版本。**要求每项摘要主张有引用叶文本支持；仅定向版本有问题时，将通用版本作为两个候选重新独立审核一次。没有新审核凭据仍不可应用。
6. **普通完整句子的换行被当成不可变事实结构。**仅允许没有链接、强调、列表的完整句子换行重排；片段拼接、链接替换、列表结构破坏仍阻止。新增真实数字、责任或因果关系仍受事实审核。
7. **回答选项夹带虚构成果。**服务端仅保留“暂无可确认的信息”选项，实际事实通过已有文本框填写，避免诱导用户确认模型编造的业绩。
8. **提供方参数兼容。**实际调用确认当前模型拒绝`minimal`；保留的单报告修复路径改为`low`。本次没有切换模型、关闭安全检查或绕过计费。
9. **审核只有拒绝，没有纠正反馈。**针对摘要追加一次有界收窄改写，将拒绝原因和该候选既有来源交回模型；新文本重新进行确定性及语义审核。修复输出不能改来源、字段或分数；新审核不支持时仍保留原拦截。该修改在`final4`优化结束后加入，单独使用`summaryfeedback`回放失败方案并进行新生成、复评分与成对盲评，不将其混入`final4`通过率。

## 实验边界

- 使用本地 `localhost:5432/resumeflow` 的非管理员合成测试用户 `qa-blind-20260906`；已授予30天不限量权益，正常并发、公平使用和用量记录仍运行。
- 使用现有配置模型 `gemini-3.5-flash-lite`。模型名称来自配置与提供方回执，不独立证明中间服务内部模型实现。
- 四份主样本加两份扩展样本，共用虚构B2B SaaS产品经理JD。评分/规划看不到档次标签和预设瑕疵；成对盲评打乱顺序并隐藏前后身份与分数。
- 扩展样本最初用于检验未见内容，之后也进入了修复回归；最终六份样本不是独立于调试过程的大规模外部测试集。独立盲评是同一配置提供方的另一次调用，不是人工专家或跨提供方一致性验证。
- 每份初始评分三次、优化两次；固定选择编号最小的成功基线和方案，优化后同一文本再评分三次，不选最高分、不选最佳收益。
- 测试调用真实评价、规划、回答、语义审核、安全校验和计费服务；审核通过的通用候选在内存组装后评分。**不是HTTP start/apply/finalize，也不是浏览器采用/撤销或生产部署验收。**
- 网页登录测试账号仍待用户注册后提供Logto用户ID；内部身份本身不能网页登录。没有把当前主账号的真实简历当作测试数据。

## 完整六样本回归结果（final4）

同一评分算法版本，初始及优化后分别重复3次。优化后使用首个成功方案，绝不选择最高分；H4Q1复评分有一次连接失败，表中只展示两份有效报告。

| 样本 | 类型 | 初始分数 | 优化后分数 | 均值变化 | 最大单维极差：前/后 |
|---|---|---|---|---:|---:|
| R7K2 | 低质量、事实不足 | 37 / 32 / 37 | 38 / 43 / 41 | +5.33 | 25 / 13 |
| R2M9 | 定性经历、缺句号 | 68 / 70 / 68 | 67 / 68 / 67 | -1.33 | 8 / 8 |
| R8P4 | 高质量对照 | 100 / 100 / 100 | 100 / 100 / 100 | 0 | 0 / 0 |
| R3V6 | 来源充分、当前表达退化 | 63 / 62 / 59 | 93 / 92 / 94 | +31.67 | 15 / 17 |
| H4Q1 | 扩展高质量对照 | 99 / 99 / 99 | 99 / 99（1次连接失败） | 0 | 0 / 0 |
| H9S2 | 定性结果、有过程数量 | 81 / 81 / 81 | 83 / 86 / 85 | +3.67 | 5 / 10 |

- 初始评价18/18成功，复评分17/18成功；失败为提供方连接错误，不算零分或通过。118次评分内部采样中103份有效、14份证据契约失败、1次连接失败；它们与用户级35/36成功是不同统计口径。
- 优化11/12成功（91.7%）：7个有实际改动方案、4个高质量无改动方案。失败发生在R2M9第1次，经历引用越过目标经历范围，仍被严格拒绝。
- 完整返回的方案有16个`rewrite_now`候选，14个允许（87.5%）；两个被拒候选都是R3V6摘要。该比例不包含未能生成完整方案的候选，也不把无数据或只读字段算成拒绝。
- 六份样本的总分极差均不超过5；每份所有维度极差均不超过10的标准，优化前4/6、优化后4/6满足。低质量样本和表述退化样本仍未满足维度稳定要求。不能说“大波动已全部解决”。
- 初始评分中位耗时96.98秒、最大122.41秒；复评分中位63.08秒。原始单次评价中位约20.47秒。优化本轮中位23.43秒，最大46.97秒。

### 文本修复与独立盲评

6/6成对盲评调用成功：四份有缺陷样本均偏好优化后版本，两份内容相同的高质量对照均为平局。第一份采用文本的盲评均未报告新增无依据主张；这不是对每个候选、所有未来输出或现实真实性的证明。

- R2M9和H9S2补齐行动句末标点，未虚构业务结果；盲评认为文本更规范，但R2M9均分下降1.33，说明小修复的收益仍会被评分噪声掩盖，**不能承诺优化后必然提分**。
- R3V6两次都恢复来源中的具体行动、量化结果和归因限制，行动重复消失；摘要仍被拦，重复问题留下，因此随后增加独立摘要反馈回归。
- R7K2去除了摘要中的绝对化自夸，但经历的空泛重复和句末标点仍留下。缺失的S/T/R事实没有编造，这是必要边界；重复和标点仍属于应改而未稳定改好的问题。
- R8P4和H4Q1没有被无理由改写。尤其原始对照误报的`。<br>`缺句号问题，在本轮两个高质量对照的成对盲评中没有出现。

机器可复核记录：`2026-09-06-resume-blind-final4/metrics.json`、`summary.json`、`member-*.json`和各次原始调用文件。评分分档绝对值因规则改变而变化；表中收益仅比较本轮同版本前后，不能用原始旧报告分数计算。

### 摘要反馈补充回归

在完整回归优化结束后增加摘要反馈修复，评分代码没有变化。`summaryfeedback`单独保留2份实际失败方案回放、2次全新规划、首个成功规划的3次复评分与盲评；不得用补充成功覆盖完整回归的失败。

两份实际被拒摘要回放均收窄到已有产品经历和SQL、Excel、需求分析/PRD技能，重新审核通过。新的空泛或无依据词语不能因为是“修复结果”就直接采用。

- **真实失败回放2/2修复成功**，均触发摘要反馈重写并获得新的支持凭据。
- **全新优化1/2成功**：第1次提供方返回无效JSON，不能算成功；第2次5个修改均可采用，摘要通过通用候选复核恢复。这次成功没有触发摘要反馈重写分支，不能拿它替代前述真实回放的分支证据。
- 首个成功的新方案三次复评分为**100 / 100 / 100**，相对于同算法基线63 / 62 / 59，均值增加38.67。六维均无波动。100由五维100、完整度97的平均99.5按既有规则四舍五入得出；缺少电话的问题仍存在，不能理解为毫无缺点。
- 独立成对盲评偏好修改后版本，未报告重复、遗漏量化或新增无依据主张。来源中的归因限制仍保留。此结果来自模型判断，不是对现实真实性或任意程度修饰词的人工核验。
- 完整`final4`与补充探针的评分代码哈希一致，只有`semantic_review.py`不同；两组收益可以基于相同评分算法分析，但各组服务成功率仍单独列示。

## 成本和限制

常规评分约需原来三倍模型调用，延迟明显增加；失败补样本最多五次，仍可能由于证据契约或提供方超时失败。中心报告选择降低异常样本影响，不能保证任意输入每次同分，也不能保证任何优化都提分。只修标点可能被评分噪声掩盖；缺失事实必须等待真实补充。

测试用户累计用量账本记录670条事件、6,290,081个提供方报告token，包含原始测试、失败诊断、调参实验、所有中间轮次和最终回归，不能当作单轮成本；计数也不保证每个失败请求的提供方成本都已报告。明细见`2026-09-06-resume-blind-summaryfeedback/usage-cumulative.json`。

旧报告不会静默重新计分。优化收益只能在同一算法版本下比较，应先重新生成基线，不能拿旧规则总分与新规则优化后分数相减。

大量调用还触发了已有不限量用量告警的数据库日期参数错误（字符串传给DATE参数）。本次未修改该独立计费告警模块；需要与算法结果区分，不能将此次测试当作计费告警验收。
