# 技能事实确认、表达策略与指标审阅实施记录

已完成本地实现与工程验证。**真实模型验收尚未通过，v4灰度继续关闭。** 全部实验只使用 `gemini-3.5-flash-lite / medium`，没有新增审核、修复或自动复评调用。

## 实现行为

- 评分结构升级为 `review_json_schema_v3`，当前提示词为 `resume_review_prompt_v6_2`，指南为 `early_career_roles_v4`。六维、权重、量表 `evidence_rubric_v2` 不变。
- 程序从原文建立片段目录，包含来源、Unicode字符起止区间与原文；模型只选择片段ID。报告展示程序提取的文字，校验未知片段、跨经历引用、重复或缺失明细。
- 每段经历输出 `expressionPlan`：保留、压缩、前置与建议阅读顺序；输出 `metricReview`：含义、范围、比较条件、验证方式与结论边界。需要调整的内容必须关联诊断，需要确认的指标必须关联事实问题。
- 技能建议增加动作分类。技能正文与分类使用 `skill_text` 目标，服务端强制转换为确认流程，并用固定说明替换技能建议的自由改写指令；只有技能排序可直接整理已有ID。
- 现有问答页新增技能确认表单，显示原文、逐行确认的文字片段和分类。确认默认关闭，编辑后取消确认；跳过保留原文。程序以分号组合用户确认的片段，既不要求模型自由改写，也不自行升级程度。
- 纯技能规划与确认后的候选生成不需要模型调用；混合模块最多一次普通规划和一次回答后批量改写。每个修改项须回答其全部问题；缺失或终止回答不解锁该项。跨字段重排若没有选中全部相关字段，保留原文并给出手动调整说明。
- 候选应用前再次核对保存的确认内容，拒绝候选被替换成其他文字。写入 `resume.config.skillOverrides[技能ID]`，不写共享技能库，不新增/删除技能条目，不使用数字 `proficiency` 推导文字程度。
- 编辑器、列表预览、PDF预览/导出、评分及JD上下文统一读取当前简历的覆盖值。保存保留该配置，内容进入签名；提供恢复技能库原文操作。撤销恢复旧覆盖值或删除本次新增覆盖映射。
- 应用核对当前账户、简历版本、已选技能、实际技能存在性和可见原文；技能删除或内容冲突不继续写入。撤销校验修改日志与候选，其他技能覆盖值不被改动。
- 新方案使用 `json_structure_v2`。旧报告仍可阅读，旧方案继续原应用/撤销分支；两种简单策略都不会回到历史审核链路。新方案要求当前评分结构版本。

|---|---|---:|---:|---|

第一版提示词正文说明了新字段，但完整JSON示例仍是旧结构，这是工程中的协议冲突。诊断调用保存了原始模型输出，确认它按旧示例返回。修正后增加“示例顶层字段与Schema必填字段一致”的回归测试，版本升为v6_1；没有在同一评分请求中自动修复或重试。请求体包含原生Schema也不能据此宣称该中转通道可靠执行了所有结构约束。

v6_1单次成功只能证明协议可以跑通。该输出仍把高信息密度当成无需压缩，把列出数值/基线当成解释与验证充分，还将耗时上限称为平均耗时，因此不计质量通过。v6_2进一步明确五个方面的区别、结论边界和表达策略；其最终冻结批次发生连续超时，没有获得可用于质量评估的输出。

运行器按已有规则在连续两次超时后停止尚未发起的成员；C当时已在途，保留其超时结果。**未发起不算失败模型输出或成功样本，也不能称已完成12次真实验收。** 没有绕过规则继续换模型或无限重试。

当前不能计算新版本的27项覆盖率、建议准确率、D三次策略表现或成功请求P95；它们应标记“未完成”，不是填0或沿用旧版本成绩。后续应在同一模型通道恢复后，用新的独立输出目录重跑完整批次，保留本轮记录。开发对照仍不能替代32份基础简历与双HR独立验收。
