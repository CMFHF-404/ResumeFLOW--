# 追问与字段契约修复

本轮完成两项工程修复：让最终问题保留对象与可核实的指标语境，以及让普通正文建议的schema与服务端默认行为一致。没有切换模型、启用灰度或增加评分、审核、修复、复评调用。

## 新行为

- 新报告使用 `resume_review_prompt_v10`，继续使用 `review_json_schema_v6`、原六维量表与计分。`metadata.factQuestionVersion=contextual_fact_questions_v1` 标识新的问题呈现方式。
- 最终问题带经历名称和单位。原因中提及的百分比，只有在本对象实际引用的原文中也存在时才作为提示显示；不复制原因里的新工具、理想答案或其他经历的数字。这只是原文显示提取，不参与评分、事实判真或写入授权。
- 工作/效率测量不再固定要求“运行、性能或资源”；验证问题涵盖复核、验收和实际验证流程，不再把财务工作一律套进实验样本模板。已写明的信息可直接沿用，缺少记录可保留未知。
- 结构化 `targetRole` 已存在时移除重复的 `target_role` 问题。若一条建议只剩这项已知信息，将其标为不可执行提醒，保留原文；不会把缺少确认的ask_user降为直接改写。混合建议仍保留其他真正待确认的缺口。
- 个人总结可引用其他已知经历作为支撑，程序补充其已检查的目标范围。所有模型引用仍先验证；未知引用、JD充当事实、其他经历错绑目标仍会拒绝或单项禁用。
- 普通正文等无选项操作可省略 `selectedItems`，服务端默认空数组。课程、经历排序和证书排序必须明确给出该字段。缺少课程选择不能再被解释为“清空全部课程”；明确 `[]` 才可清空课程，排序仍须通过完整排列校验。
- 旧已保存报告没有新问题版本标记时沿用原模板。新旧报告仍支持对应的上下文、规划、应用和撤销路径。

## 回放示例

A的原始Luna报告希望确认工作效率提升30%，旧问题为：

> 有哪些已实际记录的运行、性能或资源测量？没有测量的部分可以保留未知。

新生成的问题为：

> 「运营管理实习生（数据分析） · 金蝶（中国）软件有限公司」中的“30%”：测量的是哪项工作或结果？请补充尚未说明的统计范围、比较基准和测量或复核方式；没有记录的部分可以保留未知。

C的财务复核问题不再固定问评测样本，而是按对应财务实习询问复核、验收或验证的流程、范围和比较条件。

## 保留边界

“已知事实”的自动去重目前只依据结构化求职方向。自由文本中的“未做独立测试”、团队分工等仍需要模型正确阅读，程序没有用关键词规则猜测或删除这些问题。仅给对象标签也不能弥补模型遗漏专业问题。

没有改写历史评分、移动错放的strengths、丢弃失败响应或恢复内容正则审核；主体损坏仍整份拒绝，单项错误仍独立禁用。默认模型、开关和115/120秒预算不变。没有进行新一轮真实提供方、真实登录账户或物理设备验收。
