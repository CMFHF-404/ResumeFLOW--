# AI 回答校验职责

## 模块审阅 v4（新增灰度开关默认关闭）

在证据评分总开关之上启用 `ENABLE_RESUME_REVIEW_V4` 后使用 `resume_score_v4` / `evidence_rubric_v2`。新增统一阅读视图、服务端模块检查目录、18项专属档位标准、检查与诊断关联及结构化 `factGaps`。仍由模型直接判档，程序校验计算；不增加模型审核、修复或自动复评。前端配套构建开关为 `VITE_ENABLE_RESUME_REVIEW_V4`。见 [v4验收说明](qa/evidence-score/v4.md)。

## 证据评分 v3（质量验收开关默认关闭）

`ENABLE_EVIDENCE_RESUME_SCORE=true` 后，新评分使用 `resume_score_v3` / `evidence_rubric_v1`：一次模型判档，后端计算六维加权分；来源、观察项与可执行动作由程序校验。前端对应构建开关为 `VITE_ENABLE_EVIDENCE_RESUME_SCORE`，历史报告不混算。完整协议、校准工具、启用与回滚方式见 [证据评分验收说明](qa/evidence-score/README.md)。不增加审核、修复或自动复评调用。

## 默认评估：resume_score_v2 / single_pass_v1

评分和所选模块优化接受裸 JSON 或完整的 Markdown JSON 代码块外壳；只移除完整外壳后执行一次 JSON 解析，不从解释文字中截取对象、不修复缺失符号、不重生成。块内语法或必要结构错误仍明确失败。该处理独立于其他 AI 功能的历史解析器。

优化启动仍校验评分签名、当前简历与版本令牌。新流程只比较评分实际使用的简历内容与目标岗位，不将旧经历库副本或旧证据元数据作为评分新鲜度依据；所选经历版本另行按账号和简历链接验证。经历可选日期的缺省与 `null` 等价，具体日期值变化仍视为版本内容冲突。

新六维评分每次仅生成一次：模型返回六维分数、简短评语及模块改进方向，服务端计算六维等权平均总分（四舍五入），分配建议 ID 并解析目标模块。模型不能提交任意写入地址。公开报告包含 `dimensions`、`summary`、`suggestions`，独立 JD 匹配仍使用 `jdMatch`。

仅检查 JSON 语法和应用必需的结构：字段类型、完整且不重复的六维、0–100 分数以及存在的目标模块。允许额外字段，可选建议缺省为空。不进行证据逐字匹配、业务正则判定、扣分分项复算、多样本共识、量表审核或事实 AI 审核。格式无效直接报错，用户可手动重试；没有自动修复、重新生成或隐式提供方重试。提示词继续要求依据用户材料、不编造内容。

关联优化使用 `json_structure_v1` / `resume_optimization_single_pass_v1`：用户在报告中勾选模块后才生成方案；`selectedSuggestionIds` 在请求中发送为 `selected_suggestion_ids`，与当前报告、简历版本共同绑定。一次规划返回改写或必要问题，有效回答最多触发一次批量改写；无数据、不确定或跳过不调用模型，保留已有候选或原文。新候选状态 `not_reviewed` 仅用于区分历史协议，不表示已通过审核，不依赖 `sourceRefs` 或语义凭据。

应用仍检查用户归属、字段写入范围、排序 ID、请求幂等和当前版本，并清理不安全 HTML。删除的是内容质量与事实审核，不是账号或数据保存保护。应用只保存用户接受的修改，完成于 `applied`，将旧评分标为过期；不会自动复评或要求 finalize。用户手动重新评分时只生成一次，失败不撤销已保存的文本。

历史 `resume_flow_v1` 和 `guidance_audit_v1` 报告保持只读，不补算或转换；新优化必须先生成当前报告。旧已应用记录的读取和撤销继续保留，旧未应用方案不能通过公开应用入口写入。历史协议的内部兼容函数仅用于历史记录及回归测试，生产评分／新优化入口不调用它们。下面的 guidance、v3/v4 及语义审核说明是历史六维流程记录；共享给其他 AI 功能的检查仍按各自契约执行。

验证：`python -B -m unittest test_resume_score`（backend）和 `node --test tests/resumeScore.test.mjs tests/resumeOptimizationPostScoreFlow.test.mjs`（根目录），并运行 AGENTS.md 的关联回归组。新增测试覆盖单次调用、非法结构、取消、无选择零调用、跳过问答、应用 HTML 清理及手动复评。模型均被替换，不证明真实模型质量。开发预览：`/__dev/resume-template-preview?templateId=modern-slate&scoreReview=1`；追加 `scorePrint=1` 查看无标注的打印内容。

## 历史评估：guidance_audit_v1

指导评估要求已解析的结构化简历。纯文本 `resume_text`（包括 JSON 中的 `raw_text`）会在调用模型前返回 HTTP 422，错误码为 `resume_evaluation_structured_input_required`，且 `retryable=false`；请先完成简历解析。普通 JSON 简历对象与 `evaluation_scope=full_resume` 包装格式继续受支持。

新评估的成功路径固定为一次语义判断生成、一次独立审核。生成无效时立即结束；审核拒绝、连接失败、鉴权/配置错误及取消均不会触发自动重生成。生成与审核的性能目标分别为 50 秒和 35 秒，外层保留 150 秒安全上限；性能目标不作为单独的提前中断期限，也不等于真实延迟或成功率已经达标。

同一次评估的两次 Gemini 请求复用一个操作内 HTTP 连接池，以减少重复 TLS 握手；提示与请求体仍各自独立。连接池在该操作结束或取消后关闭，不跨用户请求复用，也不增加连接失败重试。

`guidance_tasks.py` 从冻结原文建立完整任务与来源范围。模型只返回每个语义任务的 `assessment/sourceRefs/reason/guidance`；确定性覆盖、空字段、标点及数字候选由服务端处理。模型无法提供分数、问题 ID、字段身份或排序数字。严格 JSON 模式拒绝重复键和拼接的替代报告。

每个任务还绑定允许的 `(guidance.type, guidance.prompt)` 精确组合与公开判断描述。模型只能选择已有安全动作，不得自由追加工具、职责、指标或结果示例；Schema 限定菜单字符串，服务端校验配对，越界直接使生成失败，不替换、不删改后发布。需要补充事实的动作不能冒充直接整理。模型自由 `reason` 仅作为私有审核材料，公开问题和优化依据使用服务端描述。

STAR Result 明确区分实际交付、含义不完整的结果和无产物的泛称完成。已确认的定性上线、交付、验收或投入使用不能因为缺少业务指标被降级；否定、计划和假设不被当成已发生结果。量化证据不足只进入相应量化任务，不能再作为 STAR 或因果问题重复计算。

`guidance_evaluation.py` 组装公开指导与私有评分依据，审核逐项检查来源、判断、可执行性和安全性。核心任务必须全部获准；仅可执行性不足的可选建议允许隐藏，核心判断保留。重复建议只在同字段、同分类下合并，不能借合并消除非法判断。

公开报告只展示等级、问题、建议和风险；`jdMatch` 仅镜像独立的 JD 匹配结果。数值依据、任务和完整审核结果存入当前用户的私有用量事件。公开 `auditReceipt` 绑定原文、任务、判断、量表及 Schema；优化前重新构建任务并复现报告，缺失、变更或不匹配均拒绝。无计费上下文的离线验收不写数据库，因此这类报告不能作为已持久化优化凭据。

整体状态仅由六个公开维度等级按固定锚点聚合，并沿用风险上限；内部细分分数不直接影响公开整体等级。因此同一六维等级组合必定得到同一整体状态，维度改善不会让整体变差。锚点与聚合规则一起进入量表哈希，内部原始总分保留作回归和排序，不能用历史凭据混算。

指导排序同时使用严重度、来源可信度、安全整理可行性和声明岗位的固定相关性策略；未识别岗位使用中性权重。岗位相关性只调整已有建议的顺序，不改变判断、等级或新增岗位要求，其策略内容与量表共同绑定到审核凭据。

旧 `coverage_consensus_v4` 数据保留读取，不批量回填，不重新解释，也不用于新优化或跨版本比较。旧数值基准的 `run`、wave、holdout、final、direct、score pilot、decode probe 和 summary feedback probe 已停止实时运行，在读取运行数据、写文件、计费或调用模型前提示改用 `qa_guidance_audit.py` 和新运行名。历史数值结果仍可使用原汇总工具读取。下文 v3/v4 的采样及评分说明仅记录历史实现。真实验收协议与冻结运行入口见 [guidance_audit_v1_protocol.md](qa/guidance_audit_v1_protocol.md)；自动化校验不代表真实模型准确性或浏览器验收。

六维优化使用 `evidence_semantic_v2`。方案生成和回答后的文本改写，在确定性检查通过后，各增加一次批量语义审核调用，沿用现有 AI 路由、用量计费和运行预算。纯排序、保持原文及清空个人摘要无需调用语义审核。

- **确定性检查**：字段白名单、枚举、ID、冻结原值、来源范围、数字与单位及对应关系、富文本结构、评分范围和算术一致性。错误在调用语义审核前拦截。
- **语义审核**：由独立模型调用判断候选是否受允许来源支持，包括责任、因果、技能、工具、组织关系及奖项等。审核只接收当前改写的可见文本和已通过范围检查的引用来源；不接收整份经历库或 JD。用户自述只能作为自述证据，不能证明现实真实性。
- **审核结果**：`supported` 可放行，`unsupported` 阻止应用，`uncertain` 保持待确认且不可应用。模型返回漏项、重复项、未知 ID、额外字段、非法枚举或空理由，整个审核失败；超时和取消不生成成功凭据。
- **应用绑定**：服务端将审核结论绑定到策略版本、目标字段、两个候选、原文及引用来源的哈希。应用时重新检查，不再调用 AI；无凭据、旧策略或内容已变化均不可应用。审核凭据不能由生成模型或应用请求提交。
- **历史记录**：`thin_safety_v1` 记录仍可读取；未审核的历史文本改写需要重新生成方案。已应用记录的历史展示和撤销保留原有逻辑。
- **六维评估**：新生成报告采用字段完整度与量化证据覆盖率校准。基础信息、教育、经历必要字段等按可确认字段计算；量化先由模型绑定证据，再按不同经历的覆盖比例计算，代码排除日期字段、正文日历日期、否定/条件数量和没有数量的泛化文本。前后对比至少需要同一经历内同单位的两项数值；这只是必要条件，业务含义仍依赖模型判断。存在已识别的夸大风险时，客观与可信不能同时获得正分。代码不使用中文业务关键词给结果贴分类标签。
- **评分发布（v4）**：通常两次独立生成加一次批量量表审核。生成、审核、传输失败合计最多五次，每次最长40秒，整体仍受150秒限制。为审核预留调用额度与时间；该评分路径关闭传输层隐式重试，由上层统一计数。至少两份通过审核且总分差不超过5、任一维度差不超过10的报告才可发布。审核不能改分或提供替代报告；继续选取完整 medoid，不拼接、不平均、不挑高分。跨请求的三次重复评分仍须单独验证稳定性。
- **专业表达口径**：按经历等权评估行动、术语、精确度、责任边界与客观措辞。岗位匹配、资历、业务成果大小不混入该维度；定性结果、协作职责和用户自述不自动等于不客观。重复空泛摘要主要归入可读性，不能抹去经历已有证据；实际夸大或矛盾仍应扣分。
- **修复调用兼容性**：保留的单报告修复路径使用`low`思考级别；当前提供方对配置模型的`minimal`请求返回400。评分分项的最大值也写入输出schema，服务端继续独立校验，不能假设提供方必然遵守schema。
- **回答补充**：`no_data`、`unknown`不调用生成模型；若首次规划已保存仅引用目标原文的安全整理备用候选，则复用并经过现有确定性与语义审核，供用户选择。没有备用候选时保留原文。`not_my_work`、`skipped`以及已拦截的字段不恢复备用候选。真实回答优先使用回答改写并作废备用候选。真实填写的回答采用候选补丁协议，固定身份和原文由服务端补齐；来源路径与可用变更ID写入schema。缺少独立定向候选时可复用通用候选，仍需事实审核。旧格式若显式改变固定身份，继续拒绝。
- **提问选项**：不展示模型生成的成果示例或数字选项；仅保留无数据选项，真实内容由用户在现有文本框填写。
- **候选复核**：定向版本导致联合审核未通过、且通用版本不同的情况下，可将通用候选作为两种版本重新独立审核一次。只有新审核支持时才放行，凭据绑定新的两个候选；通用内容也缺乏依据时仍保留原拦截结果。
- **摘要反馈修复**：摘要仍被语义审核拒绝时，最多追加一次30秒内的收窄改写，只传该候选既有的可见来源和拒绝原因，不能改变来源、字段身份或评分。新文本必须再次通过确定性检查和独立语义审核；无效回复、仍不支持或局部超时保留原拦截，用户取消和计费错误继续传播。不会循环重试，也不在实际应用时生成文本。
- **富文本与来源**：没有链接、强调或列表的普通完整句子允许换行重排；片段拼接、链接替换、强调丢失和列表树破坏仍被拦截。摘要可以引用当前已选技能，不因此获得熟练度或新增工作事实的授权。
- **来源地址纠正**：经历引用误指向另一条已选经历时，仅在目标经历拥有完全相同、非空的同路径叶文本时绑定回目标。不同事实、未选经历、对象级引用和用户回答不纠正，仍执行原有范围及语义检查。

自动化测试使用明确的模型回复替身，覆盖语义判断与结构检查的分工、审核结果解析、来源裁剪、异步冻结、应用绑定和撤销兼容。旧关键词分类器的单元测试已由这些契约测试替代；测试通过不代表真实模型对任意表述的判断都正确。模型质量需要另行使用真实提供方和代表性语料评估。

量化校准保留模型对零分分项的判断：零分引用可用于解释缺失，不能仅凭其中出现数字就转为正分。覆盖率只统计已获正分分项中 `verified` / `user_claimed` 的证据。通用候选补充审核的无效回复、提供方不可用或局部超时保留首轮候选及其审核凭据；用户取消、计费/用量错误和整体期限耗尽仍终止请求。

已获模型支持的真实成果可出现在任一 STAR 字段，结果指标不会因写在行动字段而被清零。前后端使用同一组换行合并样例验证可采用边界：完整纯文本句子可合并，片段、链接、强调和列表继续执行结构保护。`qa_resume_blind_wave.py` 在任何输出或缓存复用前校验算法哈希；同名波次版本变化、清单损坏或已有结果缺少清单时，必须改用新名称，原证据保持不变。

摘要补救另外接收原摘要的 `beforeRichText` 格式模板，保留链接目标及允许的格式，剔除隐藏内容和非必要 HTML 属性。模板只用于保留格式，不能替代来源证据；新候选仍需通过结构检查和独立语义审核。Holdout 入口 `qa_resume_blind_holdout.py` 同样在任何写入之前执行波次版本校验。

新增回归模块：`python -B -m unittest test_resume_evaluation_calibration test_resume_evaluation_consensus`。原有优化、评估、语义审核以及前端报告归一化测试仍需按变更范围运行。

历史报告不会被静默重新打分。比较优化前后的分数时，应先按当前规则重新生成基线报告，再进行优化和复评分；不能把旧规则与新规则的分数差直接当成优化收益。

新生成报告由服务端标记 `scoringVersion=coverage_consensus_v4`，与报告结构版本 `evaluationVersion` 分开。v2 在前后对比的证据覆盖统计中统一中英文固定时长单位，保留不同统计周期的区别，不将日历月份或年份视为固定天数。该规则只处理已有模型支持的证据，不改变零分、否定、条件句和日期过滤。历史报告缺少评分标记或使用 v1/v2/v3 时仍可读取，但前端优化入口及后端冻结上下文均要求重新评分；旧方案在应用前也会被拦截。已应用的旧方案无法与新评分混算，返回不可重试的明确提示，要求撤销后重新评分并生成方案。报告归一化保留已有评分版本，不能自行给历史数据补上当前标记。

完整度校准按未填写的具体字段重建问题与优先建议，包括第几条教育/工作经历及缺少的学校、专业、日期等；已补齐字段不再产生对应建议，其他维度的问题保持原有记录。

### QA 运行与证据复用

`qa_resume_blind_final.py` 和 `qa_resume_summary_feedback_probe.py` 在任何写入或缓存复用前，校验 `run-manifest.json` 绑定的算法及脚本哈希、样本、标签、来源和固定协议。相同输入的续跑保留原始元数据；代码、输入或协议变化、元数据损坏、旧目录缺少清单时均拒绝复用，要求新的运行名称。清单记录创建时间，协议中的时间不参与续跑时重新生成。

清单还绑定 `runtime-config.json`：使用调用层实际解析的默认路由、提供方、模型、传输方式、端点哈希、超时和 AI 预算。上述配置变化同样要求新运行名；不保存 API 密钥或完整端点 URL，单纯轮换 API 密钥不改变配置指纹。最终回归的每条 `member-*.json` 采样使用独立 UUID 和排他创建，中断续跑保留此前成功及失败记录，成员级统计继续包含这些已完成的尝试。

摘要反馈探针使用 `python qa_resume_summary_feedback_probe.py <新的字母数字运行名>`。`final4` 仅提供合成样本和失败方案回放；每个新运行先生成三次当前版本基线，以编号最小的成功基线规划，再对首个成功方案复评三次。没有有效基线或报告评分版本不符时停止，不混用历史评分。旧 `summaryfeedback` 结果目录保持原样。

离线回归：`python -B -m unittest test_qa_resume_frozen_runs test_qa_resume_wave_state`。测试使用临时目录和模拟调用，不触发真实 AI、计费或数据库操作；修复脚本本身不构成新一轮真实模型验收。


### v3 字段覆盖和扣分绑定

规划按问题与目标字段记录覆盖，同一问题涉及多字段时分别处理；每字段仍最多一个可应用候选。服务端补齐已有行动标点，以及同一已选来源中可安全补回的完整成果。完整来源回填仅用于不携带独有事实的泛化完成句，保留来源的时间、主体和归因限制，仍必须通过安全审核。包含独有事实、冲突或不明确来源的字段保留并记录原因，不能把任意来源文本强行覆盖到原文。

`coverage`、`cleanup_fallbacks` 仅用于内部计划持久化，不出现在公共预览或应用接口中；旧计划缺失时默认为空。覆盖的候选状态不是用户采纳或缺陷完全修复证明，盲测另核对两次实际文本。

v3 主生成的每个子项提供内部 `deductionIssueId`：满分为空，扣分时指向同维度的具体问题；服务器按该子项差额汇总问题扣分，不在无关问题间分摊。专业表达扣分必须有文本证据。公开报告保持原结构；历史报告不会套用新绑定补算。专业表达采用明确的五项证据锚点，不以术语数量、资历或业务数字缺失计分。

内部诊断只记录校验阶段、错误分类及受控字段路径；不记录异常原文、密钥或完整提供方地址。短暂连接失败计为失败采样，鉴权/配置错误立即返回，取消继续向上传播。

v3 盲测记录保持不变；当前完整验收必须使用下述 v4 审核前置门槛。

### v4 服务端任务与独立量表审核

新规划协议为 `resume_optimization_tasks_v2`。服务端先构造完整内部任务表，将字段原值、模块、问题、展示维度和来源映射固定；无需模型判断或不能安全定位的字段明确保留。模型仅为可编辑任务返回内容补丁和任务内来源编号。动态 schema 的任务键全部必填；未知来源、缺失任务、非法额外身份字段均失败，不通过丢弃坏补丁制造成功。标点及可安全补回的完整成果候选在生成前准备。原有技能及模块排序仍只允许当前 ID 的排列，不可新增或删除。

同字段多维度问题由服务端分组，只有一个可应用修改；其他问题保留关联。独立的覆盖审核与事实安全审核在同一请求完成：事实安全通过不等于缺陷修复。覆盖结论绑定问题和候选输入，后续恢复导致内容变化时原结论失效；回答后的候选同样审核覆盖。

`planning_tasks`、来源映射、整理备用候选和覆盖结论不进入公共预览字段。旧规划协议仍可读取，不补造任务或审核记录。

评分审核版本为 `resume_rubric_audit_v3`。审核看到当前事实、六维量表、子项分数与证据理由，不接收总分或原版/优化版身份。每份报告六个维度必须各返回一次“符合／不符合／不确定”，不得修改分数。既检查无依据扣分，也检查无依据加分；有引用并不能替代判断引用是否支持结论。语义拒绝不反复审核同一报告直至获准；不足两份合格报告且剩余预算无法补足时提前失败。

审核提示词明确要求只输出 JSON，并嵌入与提供方结构化参数相同的动态 schema，避免仅依赖网关执行 schema。服务端仍完整校验响应，不从自由文本猜测审核结果。审核凭据同时绑定响应 schema；修改输出契约后旧凭据不能复用。`qa_resume_v4_response_probe.py` 只做一次独立诊断，记录请求结构化参数和正文形态特征，不保存提供方正文，也不计为盲测或门槛成功样本。

评分审核凭据绑定完整报告、事实输入、量表与审核版本哈希，追加到本次审核调用的现有用量事件内部元数据。公开用量接口过滤这些新增字段，不改变原计费、额度或告警规则。不合格、审核不确定或分歧未解决时返回可重试错误 `resume_evaluation_rubric_unconfirmed`，不发布参考分数。公开评分结构保持不变。

验证顺序：先跑离线回归，再执行 `python -B qa_resume_v4_audit_gate.py <新门槛运行名>`。该回放冻结九个正反例，覆盖专业表达、求职方向、轻微标点和过程数量/数据可信度，打乱顺序执行两轮。每例明确目标维度，全部目标判断均须正确；它仍不能代替整份报告与跨请求稳定性验收。测试样例本身先通过引用、算术和具体扣分理由检查。

两轮全部正确后，才能运行 `python -B qa_resume_blind_final.py <新完整运行名> --v4-holdouts --audit-gate <门槛运行名>`，覆盖原八份回归样本和两份新留出样本。入口重新核对真实判断、冻结清单、当前代码与配置，不能仅用一个绿色汇总文件解锁。门槛失败则停止扩大测试。新 QA 子进程显式关闭外部 webhook 通知，记录该非敏感配置，不更改全局环境。

规划及覆盖审核也在系统提示词嵌入与请求参数相同的完整 JSON schema。单任务补丁缺失项记录服务端任务路径、已知缺失字段和额外字段数量，不回显未知键或正文。

评分生成和量表审核共用 `resume_evaluation_rubric.py` 中的证据规则；它明确专业表达逐经历判断再汇总、求职方向证据边界、轻微标点扣分与过程数字的计分归属，不按关键词密度计分。共享规则及版本进入审核凭据哈希。仅有技能名称不支持新熟练程度声明；本地安全校验要求该程度声明有对应原文，不能被模型的 supported 判定覆盖。

评分首次生成同时提供内部 `evidenceBasis`（`resume_evidence_basis_v4`），不增加模型调用。服务端固定逐经历、逐专业表达子项的证据范围；模型判断具体缺陷及程度，服务端按共享锚点计算分数。专业表达以一个 `assessment` 枚举同时选择程度和缺陷，schema 不再提供“无缺陷满分却又声明具体缺陷”的相互矛盾组合；返回非法值或旧的双字段组合仍拒绝。求职方向也仅从简历内证据判断。未知引用、跨经历引用、缺失评估项及扣分绑定矛盾仍拒绝，不以重算数值挽救语义错误。内部清单不进入公共评分结构，完整报告继续经过独立量表审核。

标点候选复用富文本规范化边界，只检测缺失的句末标记，不修改评分输入。模型区分完整表述与标题、标签、片段；服务端对完整表述逐处扣 1 分，合计最多 3 分。真正的非标点语法缺陷另行提供证据，不能将重复表达、数字缺失或空泛工作混入语法扣分。独立审核仍检查错误的分类和理由。

共享量表 `resume_evidence_anchors_v4_3` 进一步明确：STAR 行动字段非空不代表行动充分，只有职能标签或未说明具体动作、对象的占位表达不能获得接近满分；简单但具体的工作可以充分得分，不要求高级职责或数字。STAR 执行细节与专业表达措辞如分别扣分，必须说明各自不同的缺陷，不能复制同一理由重复扣分。该共享量表变化使旧审核凭据和旧冻结门槛不能用于当前代码的完整验收。

内部 STAR 评估逐经历返回内容类别及同经历事实引用，由服务端按统一分值取均值并四舍五入：情境/任务为完整 15、部分 8、缺失 0；行动为具体执行 35、部分执行 18、纯泛化职能 10、缺失 0；结果为明确成果 35、部分成果 18、泛化完成 10、缺失 0。定性验收、交付或上线可以是明确成果；成果位于同一经历的行动字段也可计入，观察期和归因限制完整保留。无证据、跨经历借用或未知类别仍拒绝；类别是否符合原文继续由独立量表审核判断。

已有夸大风险使“客观与可信”归零的校准规则，提前在扣分绑定前执行，避免原本有依据的风险扣分被误认为满分矛盾。模型已绑定的问题保留并继续校验；空绑定由服务端添加带原风险引用的固定说明。不丢弃未知绑定或孤立问题，不把风险标志视为语义认可，独立审核仍须拒绝无依据风险。

发布前的内部 `audited_score_profile` 只记录审核通过报告的绑定哈希、固定量表顺序的维度/子项数值和极差，不记录简历、理由、证据原文或提供方响应。不合格报告不能混入这些数值；单份报告的极差记为空。该诊断用于定位“全部审核通过但仍分歧”的失败，不新增公共评分状态，也不代表跨请求重复评分稳定。

完整盲测可加 `--service-batch-size 3` 分批执行，每次最多新增三个服务请求；这是服务请求上限，不是提供方调用数（每个评分仍有最多五次尝试）。批次大小写入冻结协议，续跑必须使用相同参数和代码。所有十个样本及三次基线、两次优化、三次复评分、一次盲评保持不变。已有成功与失败均复用，不重新生成；只有完成所有可执行阶段才写入 `finished.json`，上游失败导致的缺失仍在验收分母中单列。

每批追加独立 `batch-*.json` 并更新 `progress.json`，记录本批启动和暂缓的服务以及完整预定阶段数量。暂缓不表示成功或失败，部分批次不能宣称完整验收通过。鉴权和配置错误会阻止本进程继续启动新请求，已经发出的请求正常收尾。续跑同一已完成轮次不会改写完成记录。

受控诊断脚本 `python -B qa_resume_score_pilot.py <新运行名> --sample R7K2` 可只复测一个固定问题样本；省略 `--sample` 时为 R7K2、N6D2 两份。样本选择、请求数、代码和配置均冻结；每次请求维持五次尝试及 150 秒上限，鉴权或配置错误停止后续请求，不覆盖失败记录。这是定位问题的小批诊断，不能替代完整盲测、覆盖核对或重复评分稳定性验收。
